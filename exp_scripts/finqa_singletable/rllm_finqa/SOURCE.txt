Byte-identical copies of the FinQA environment the PRPO FinQA runs used, so SAO and
PRPO see the same prompt, tools, tool-output truncation, turn limit and judge.
The SAO code never imports rllm: finqa_env.py loads these files with minimal
in-memory stand-ins for the three rllm names they reference (a no-op decorator
and two plain data classes); nothing from rllm is executed.

Source: https://github.com/rllm-org/rllm @ 3b40c37c (2026-09-05), cookbooks/finqa/
  finqa_constants.py, finqa_tools.py, finqa_flow.py, prompts/*.txt  unchanged upstream files
  finqa_eval.py  the working-tree version PRPO ran with (local edit of 2026-08-28):
                 judge model read from FINQA_JUDGE_MODEL (default gpt-5.4-nano; upstream
                 hardcodes gpt-5-nano, not deployed on our Azure) and up to
                 FINQA_JUDGE_MAX_ATTEMPTS retries when the judge returns a non-"stop"
                 finish (upstream scores an empty/truncated judge reply as wrong).
finqa_flow.py is kept for reference and for its pure helpers (_exec_tool_call,
_msg_to_dict, _truncate, SYSTEM_PROMPT, MAX_TURNS); its rollout function is not
used, because SAO must route each model call through Reef for a receipt and must
set sampling explicitly (in rllm the gateway set it).
